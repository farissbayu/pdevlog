## What this repo does

A private, single-user dev log. The React 19 SPA and the Hono API ship as **one
Cloudflare Worker** (`@cloudflare/vite-plugin`). Data lives in **D1 (SQLite)** via
Drizzle, images live in **R2** (served through an owner-checked proxy), AI runs
through any OpenAI-compatible endpoint (OpenRouter in practice), and sessions are
signed JWT cookies from Google OAuth.

Features: workspaces, brag logs (STAR), notes with sources, sparks inbox,
screenshot attachments, tags, dashboard, export, a profile/CV audit, and projects.
(Skills radar and skill-shredder are being retired.) Deploy is CI-driven
(`.github/workflows/deploy.yml`: typecheck → test → remote migrations → deploy).

## Load assumed

- One primary developer plus a handful of accounts (the app is described as
  "private").
- Low request concurrency; no queue, no cron. Long AI work uses
  `executionCtx.waitUntil` + client polling.
- Every AI call costs real money through OpenRouter. This makes AI endpoints a
  cost-abuse surface even at tiny user counts.

## Must fix

### 1. AI endpoints are not rate limited

**Location:** `src/worker/features/profile/route.ts:204-210`

- **What this is:** `star-breakdown` (`brag-logs/route.ts:605`) is wrapped in
  `rateLimit(10/min)`. The profile AI routes — `/profile/cv/upload`,
  `/profile/cv/sync-skills`, `/profile/skills/analyze`, `/profile/persona/extract`
  — have no limiter.
- **Problem:** Each is a paid OpenRouter request. A single account (or a script)
  can hammer them.
- **Fix:** Apply the existing `rateLimit(...)` middleware to those four routes.
  No new code.
- **If we skip it:** Unbounded spend and a trivial DoS on your own AI quota.

## Should fix

### 2. Check-then-insert races on "create if missing"

**Location:** `src/worker/features/profile/service.ts:84-109`
(`getOrCreateProfile`), `src/worker/features/auth/route.ts:75-110` (`upsertUser`)

- **What this is:** Each reads first, then inserts only when absent.
- **Problem:** Two concurrent first-requests both insert; one hits the
  primary-key / unique constraint and the route returns a 500. `getOrCreateProfile`
  is called from four profile handlers, so a double-load is easy.
- **Fix:** `insert(...).values(...).onConflictDoNothing()` then re-select, or catch
  the unique error and re-select.
- **If we skip it:** Rare, non-deterministic 500s on first login / first page load.

### 3. Every list is unbounded when `page` is omitted

**Location:** `src/shared/schemas/pagination.ts:31-34` with e.g.
`notes/route.ts:526`, `brag-logs/route.ts:296`, `sparks/route.ts:201`

- **What this is:** `parsePagination` returns `page: null` when no `page` param is
  sent, and each list handler skips `.limit().offset()` in that branch.
- **Problem:** One missing query param returns the user's entire table.
  `buildPaginationMeta` then even reports `pageSize: total`. A user with thousands
  of notes loads them all into a single Worker response.
- **Fix:** Treat a missing `page` as page 1 (default 20), or hard-cap the no-page
  branch at `MAX_PAGE_SIZE`.
- **If we skip it:** Memory/time blowups as data grows, triggered by any client
  that forgets `page`.

### 4. Duplicated per-module response/query helpers

**Location:** `notes/route.ts:90-211`, `brag-logs/route.ts:72-163`,
`sparks/route.ts:57-131`, `tags/route.ts:30-49`, `dashboard/route.ts:29-107`,
`export/route.ts:23-52`

- **What this is:** `toTagResponse`, `toWorkspaceResponse`,
  `validateTagOwnership`, `loadTagsBy*Ids`, and attachment grouping are
  re-implemented per file.
- **Problem:** Every workspace/tag response-shape change must be edited in 4–6
  places; they already drift (`brag-logs` `toWorkspaceResponse` hardcodes
  `sources: []` while `notes` fills them).
- **Fix:** Move the shared mappers/loaders into
  `features/tags/helpers.ts` and `features/workspaces/helpers.ts` and import them.
- **If we skip it:** Bugs from half-applied edits, plus ~150 removable lines.

### 5. `ai-client.ts` repeats the same block for every AI feature

**Location:** `src/worker/lib/ai-client.ts` — `generateStarBreakdown:156`,
`extractAndFormatResume:441`, `analyzeDeveloperCompetencies:613`

- **What this is:** Each function re-implements the same try/catch, `parsed` /
  `refusal` extraction, token-usage reads, and "no structured output" error.
  (The retired skills functions add three more copies of the same pattern.)
- **Problem:** One copy per feature; any fix (e.g. token accounting, timeout
  handling) must be applied N times and will drift.
- **Fix:** Extract one
  `runStructuredCompletion(env, { schema, name, system, user, timeout, ErrorType })`
  helper and have each feature call it.
- **If we skip it:** ~100+ lines of duplication and divergent behavior between AI
  features.

### 6. R2 bucket is bound twice in `wrangler.jsonc`

**Location:** `wrangler.jsonc` (`r2_buckets` array)

- **What this is:** The same bucket `pdevlog-storage` is bound twice — as `STORAGE`
  and as `pdevlog_storage`.
- **Problem:** Only `STORAGE` is referenced anywhere in `src/` (grep for
  `pdevlog_storage` = 0 hits). Dead config.
- **Fix:** Delete the second binding entry.
- **If we skip it:** Confusing config; harmless at runtime.

### 7. Three dependencies are unused duplicates of `radix-ui`

**Location:** `package.json` — `@radix-ui/react-avatar`,
`@radix-ui/react-dropdown-menu`, `@radix-ui/react-slot`

- **What this is:** All UI primitives import from the `radix-ui` umbrella package.
  The three scoped packages have zero imports in `src/`.
- **Problem:** Extra install surface and a second source of truth for the same
  primitives. Related: `clsx` + `tailwind-merge` are used only by
  `src/client/lib/utils.ts`, which just two files import, while 41 files import
  `cn` from the `cn` package — two competing helpers.
- **Fix:** Remove the three scoped packages. Either delete `lib/utils.ts` and move
  its 2 callers to `cn`, or drop the `cn` dependency.
- **If we skip it:** Slower installs and an ambiguous house style.

### 8. README is stale and links to missing docs

**Location:** `README.md` (API table, Prerequisites, Deployment)

- **What this is:** It omits the profile and projects routes; links to
  `docs/google-oauth-setup.md` and `docs/DEPLOYMENT.md`, which do not exist
  (`docs/` holds only `guides/` and `plan/`); and claims `/api/health` is
  unauthenticated, while `authMiddleware` actually returns 401.
- **Problem:** A new contributor (or agent) follows dead links and misses routes.
- **Fix:** Update the route table and either add those two docs or point at
  `tasks/` and `docs/guides/`. If the skills feature is removed, drop its section
  too.
- **If we skip it:** Repeated confusion for the next reader.

### 9. R2 deletes are not atomic with the DB delete

**Location:** `notes/route.ts:982-988`, `brag-logs/route.ts:600`,
`sparks/route.ts:376-379`

- **What this is:** The DB row is deleted first; `deleteOwnedAttachments` then
  deletes the R2 objects.
- **Problem:** If the R2 call fails after the row is gone, the objects are orphaned
  with no row to find them by. (Account deletion cleans by prefix, but per-entity
  deletion does not.)
- **Fix:** Delete R2 first, then the DB row — an orphaned R2 object on failure is
  recoverable by prefix; an orphaned row without objects is not.
- **If we skip it:** A slow storage leak, invisible until the bill grows.

## Nice to have

### 10. Range response math can go negative

**Location:** `src/worker/features/attachments/route.ts:17-20`

- **What this is:** For suffix or open-ended `Range` requests, `start` / `length`
  are derived ad hoc in `buildObjectHeaders`.
- **Problem:** A malformed range can produce a negative `Content-Length`.
- **Fix:** Use R2's already-resolved `object.range` directly and clamp.
- **If we skip it:** Rare, broken downloads for unusual range requests.

### 11. Per-isolate rate-limit `Map` only cleans at ≥1000 entries

**Location:** `src/worker/middleware/rate-limit.ts:33-44`

- **What this is:** Expired entries are pruned only once the map reaches
  `CLEANUP_THRESHOLD`.
- **Problem:** Many distinct IPs within a 60 s window grow the map unboundedly per
  isolate.
- **Fix:** Prune on every call (cheap at this size) or bound the map.
- **If we skip it:** Minor memory growth under scanning traffic.

### 12. Full-text `LIKE '%q%'` scans on note content

**Location:** `src/worker/features/notes/route.ts:435-465`

- **What this is:** Up to five `LIKE` predicates across `title`, `content`, and a
  correlated `sources` subquery, per search token.
- **Problem:** Unindexable and O(n) per search.
- **Fix:** Fine at personal scale; move to FTS5 if notes reach five figures.
- **If we skip it:** Slower search as the log grows.

### 13. Profile handlers each re-query the user row

**Location:** `src/worker/features/profile/route.ts:24-202`

- **What this is:** Four handlers repeat the same
  `select ... from users where id = ?` block.
- **Problem:** Duplication; the auth middleware already proved the session.
- **Fix:** One `loadUser(db, userId)` helper.
- **If we skip it:** More copy-paste.

### 14. Non-scoped delete on owner-id-only predicate

**Location:** `src/worker/features/notes/route.ts:857-867`

- **What this is:** `delete ... where ownerType='note' and ownerId = ?` without a
  `userId` clause.
- **Problem:** Safe today only because owner ids are nanoids, but it violates the
  repo's own isolation rule.
- **Fix:** Add `and(eq(sources.userId, userId))`.
- **If we skip it:** Latent cross-user risk if ids ever become predictable.

## Retired feature (removed)

The skills / radar / skill-shredder feature was deleted (worker routes, services,
client pages, shared schemas, four D1 tables via migration `0021`). The issues
below existed while the code was live and disappeared with the deletion:

- Cross-user milestone write — `src/worker/features/skills/service.ts:382-406`
  (and `361-377`): an un-scoped `UPDATE skill_milestones` lets one user flip
  another user's milestone to "achieved".
- Blocking sync — `src/worker/features/skills/route.ts:33-38` → `service.ts:540-594`:
  `/api/skills/sync` `await`s up to 20 sequential AI calls in-request instead of
  using `202` + `waitUntil`.
- Seed cost — `src/worker/features/skills/service.ts:70-98`: `ensureUserSkills`
  does one insert per seed row on first load.

security/scale findings, the remaining priority is the un-rated paid AI endpoints
(finding 1). The rest is hygiene and can be batched.
